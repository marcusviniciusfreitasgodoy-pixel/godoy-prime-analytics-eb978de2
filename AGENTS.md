
- Amostras de ITBI acima de 1.000 linhas são lidas em páginas via `supabase/functions/_shared/fetchPaged.ts` (ordenação por id): a base SMF passa de 5.000 linhas por bairro em 60 meses.
- Calibration queries 7.4 and 7.4b produce two CSVs that feed the outlier generator. The belt floor is P0.5 × 0.85 and the ceiling P99.5 × 1.15 over individual escrituras corrected to the latest index quarter (spec section 2.5). Generate candidates outside the runtime module and apply only after the acceptance query `docs/calibracao/bloco74c-aceite.sql` passes, because failed market-coverage checks must not change live filters.
- The belt table is in latest-quarter prices while `itbi_transactions` rows are in period prices. Always filter through `getOutlierLimits`, which divides the floor by `FATOR_INDICE_5_ANOS` and the ceiling by `FATOR_MIN_INDICE_5_ANOS`; raw table numbers would cut valid older sales.
- Store calibrated pairs and the CIDADE|* fallback in itbi_cinto; filter individual corrected prices before SMF aggregation and audit by neighborhood separately, because aggregated filtering can discard good sales with a bad one. SQL loads remain explicit and acceptance-gated.
- App MCP server lives in src/lib/mcp (one tool per file, OAuth via managed auth, caller-scoped client); supabase/functions/mcp is SDK-generated, never hand-edited, and ships only on publish.
- MCP history lists use bounded pages with exact counts from the same caller-scoped query and a date-plus-id ordering; counts must never bypass RLS, and multi-page reads are not a frozen snapshot.
- Belt building rules live in `itbi_aplicar_cinto` (migration `20261021230000_itbi_cinto_regras_predio.sql`) and are mirrored in `REGRA_PREDIO` in `_shared/outlierLimits.ts`. Sales at 50% or less of same-size units in the same building are marked `fora_de_mercado` and excluded; sales above the ceiling that match their own building are kept. Change both places together and run the year-by-year simulation `docs/calibracao/bloco74d-simulacao-regras-predio.sql` before applying.
